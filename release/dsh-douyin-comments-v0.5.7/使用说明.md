# 抖音评论采集（DSH 插件）使用说明 · v0.5.7

这个压缩包里有两样东西：

| 文件 | 是什么 | 谁需要 |
| --- | --- | --- |
| `dsh-douyin-comments-0.5.7.tgz` | DSH 插件本体（**自带浏览器扩展 v0.2.9**） | 想让 AI 采抖音评论的人 |
| `douyin-collector-extension-v0.2.9.zip` | 单独一份 Chrome 扩展 | 不想用 DSH、只想在浏览器里手动装的（可选） |

装完插件，AI 就能用 `douyin_comments` 这个工具采**公开评论**并导出 CSV / JSON。

> **0.5.7 新增**（本版专治「换视频后上一条的数据没了」这个误解）：
> ① **数据其实一条都没丢，只是旧面板「只看得见当前这条视频」**。评论一直**按视频分桶**存在浏览器
>    本地（`chrome.storage.local` 里的 `dts_c_<videoId>`，一个视频一个桶），代码里除了面板上那两个
>    清空按钮（`dts-clear`）**没有任何删除路径**。真实例证：报这个问题的用户，自己 Edge 的
>    `Profile 1` 里 6 个桶全在（624 / 1406 / 2142 / 2267 / 9446 / 27 条），一条都没少。
>    旧面板的「已采（去重）」和两个导出按钮都只认「当前这条视频」，滑到下一条再点「开始采集」时
>    计数归零、面板显示 0，**看起来**像被清空了 —— 其实只是口径问题。
>    所以本版**一行数据路径都没改**，只补「跨视频可见性」和「导出全部视频」。
> ② **面板新增一行「本地已存」**（内置扩展升到 **0.2.9**）：显示 `N 个视频 / M 条（本条 X 条）`，
>    面板构建时读一次，之后每 20 秒刷新；落库后与点「清空」后立刻刷新。
>    「已采（去重）」在本轮还没落库、但本地已经有这条视频数据时，会补显 `（本地已有 N 条）`。
>    点「开始采集」时面板还会写一行
>    `本机已存：N 个视频 / M 条（含其它视频）；本条视频本地已有 X 条`，明确告诉你旧数据还在。
> ③ **面板新增一行「导出范围」**，两个互斥小按钮：
>    - **「本条视频」**（默认，和以前一样，只导当前这条视频的评论）；
>    - **「全部视频」**：把本地**所有**视频的评论合成一份导出。
>      - CSV **末尾会多一列 `video_id`**（共 18 列）；**前 17 列的列序与含义完全不变**，
>        按位置读前 17 列的老脚本/老习惯仍然正确；
>      - JSON 顶层多 `scope: "all"` 和 `videos: [{ videoId, title, count }]`，每条评论也带 `videoId`；
>      - 文件名 `douyin-comments-all-<时间戳>.csv|json`（单视频仍是
>        `douyin-comments-<videoId>-<时间戳>.csv|json`）。
>      导出是**只读**的，不会动本地任何数据。
> ④ **后台 `dts-stats` 新增 `totalAll` / `videoCount`**：跨视频总条数用 `dts_videos` 里维护的 `count`
>    元数据累加（不遍历每个评论桶），`videoCount` 是本地有几个视频 —— 「本地已存」那一行就是它。
> ⑤ **「清空」再说清楚一次**：**「清空」= 只清当前页面这条视频**；
>    **「全部清空」= 清所有视频**（红色按钮、两步确认、不可恢复）。
>    换视频、清空某一条视频**都不会**影响别的视频。
> ⑥ **自测**：离线 `verify-tool.mjs` **130/130 全绿**（上一版 121；本次新增 9 条断言，含 AI 桥 `dts-ai-export` 的 `all:true`）；
>    真机验收（临时脚本，跑完已删）**22/22 通过**：种两个视频的桶 → 换视频/没采过的视频时
>    `totalAll` 仍是 5、`videoCount` 是 2；单视频 CSV 仍 17 列 4 行、无 `video_id`；
>    「全部视频」CSV 18 列 6 行且两个 `video_id` 都在、一级 3 二级 2；「全部视频」JSON `scope=all`、
>    `videos` 2 个、5 条评论每条带 `videoId`；面板真机页面显示「本地已存 2 个视频 / 5 条」；
>    点「全部视频」后按钮选中态互斥、导出落盘文件内容正确；面板「清空」只作用于当前页面这条视频、
>    两个种子桶一条没少。配套 MCP `douyin-mcp` **没动，仍是 0.3.1**。

> **0.5.5 新增**：
> ① **修掉「脚本缓存清了、却清错地方」**（重要）：以前只清 `Default/Code Cache` 与
>    `Default/Service Worker/ScriptCache`，会留下指向已删脚本的注册库 `Default/Service Worker/Database`，
>    Chrome 因此**起不来扩展后台**——面板照样注入，但页面每次 `sendMessage` 都回
>    `Could not establish connection. Receiving end does not exist.`，表现就是
>    「点清空没反应 / 面板谎称已清空、评论一条不落库、最后交付 0 条」。
>    真机对照实测：只清 ScriptCache 跑 2 轮（1 轮正常、1 轮扩展 SW 数=0 且探活失败）；
>    改成**清掉整个 `Default/Service Worker`** 后 2/2 正常。
>    现在清 `Default/Code Cache` + 整个 `Default/Service Worker`；
> ② **采集前先检查「扩展后台可达性」，不通就自愈**：面板就绪后读页面自测的 `bgOk`/`bgErr`，
>    命中 `Receiving end does not exist|Extension context invalidated` 就刷新页面重试（最多 2 次），
>    仍不通就把这次启动标脏（`extension.launched.json` 的 hash 置空，下次强制清缓存重开），
>    并明确告诉你「扩展后台没有响应……本轮采到的评论不会落库」，**不再静默交付 0 条**；
> ③ **面板不再谎称「已清空」**：内容脚本新增主动探活（`probeBackground()`，启动 200ms 后一次、
>    之后每 30 秒一次），状态镜像与面板文案多了 `bgOk`/`bgErr`/`bgCheckedAt`；后台也多了
>    零副作用探针 `dts-ping`（只回 `{ok:true,pong:true,at}`；用 `dts-status` 探活会给
>    `updateVideoMeta` 写一条 `videoId=undefined` 的脏记录）；
> ④ **「交付 0 条」如实归因**：页面采到 N 条但扩展存储没增加时，明确报
>    「落库失败（扩展后台不可达）」，不再把锅甩给「抖音限流 / 视频没有新评论」；
> ⑤ **清空没生效会明确报错**：`clearBefore` 时点「清空」两次仍不空 → 刷新页面重试 →
>    仍不空则报错（点了 3 次仍剩 N 条），不再当成功继续；
> ⑥ 离线自测 **102/102 → 113/113**（新增 `dts-ping` 零副作用、内容脚本探活+镜像、
>    采集器 bgDead/自愈/标脏、清空 3 次报错、交付 0 条归因、`Config` 不直接链式 `.volatile()`、
>    `loadSchema` 先取宿主副本 7 条）；配套 MCP `douyin-mcp`

> ⑦ **全新 profile 里也能加载**（发布验收发现）：有些 profile 里 pnpm 会给插件装一份**旧版**
>    `@deepseek-ai/schemastery`（实测 3.18.2，没有 `Schema.prototype.volatile`），`Config` 直接链式

## 一、装插件（3 步）

前置：Windows / macOS + Node.js ≥ 22.19 + 已装好 DSH。

```powershell
# 1) 装（把路径换成你放 tgz 的位置）
dsh plugin --profile web add file:C:\Users\你\Downloads\dsh-douyin-comments-0.5.7.tgz

# 2) 重启 dsh web —— 必须重启，工具的注册表在进程启动时就冻结了
#    （关掉当前的 dsh web，再重新起）
```

3）重启后，直接对 AI 说：

> 用 douyin_comments 采集 https://www.douyin.com/video/7660328050596371819 ，max=200

也可以让它自己决定，你只要说「帮我把这个视频的评论抓下来：<链接>」。

装的时候 pnpm 会自动带上依赖 `playwright-core`（约 13 MB，驱动浏览器用，不含浏览器本体），不用你另外装。

## 二、设置（三个层次，任选其一）

### ① 扩展面板上的设置齿轮 `⚙`（0.5.3，推荐）

插件自己拉起的浏览器里，抖音页面右侧的面板**标题栏右上角**就是设置齿轮（在收起「—」左边）：

```
● 评论采集器                      [⚙] [—]
阶段                              已暂停
已采（去重）               194 条（落库 194）
本地已存                   2 个视频 / 5 条（本条 3 条）
...
[开始采集]                        [暂停]
[导出 CSV]  [导出 JSON]
导出范围        [本条视频]  [全部视频]
[清空]  [全部清空]
```

> 「**本地已存**」那一行是 0.5.7 新增的：它显示**跨视频**的总规模（`N 个视频 / M 条`），
> 换视频、清空某一条视频都不会让它清零。看到它就知道「上一条视频的数据还在」。
>
> 「**导出范围**」那两个互斥按钮也是 0.5.7 新增的：默认 `[本条视频]`（旧行为），
> 切成 `[全部视频]` 再点「导出 CSV / 导出 JSON」，就会把本地**所有视频**的评论合成一份导出
> （CSV 末尾多一列 `video_id`，文件名 `douyin-comments-all-<时间戳>.csv`）。
>
> `[清空]` 只清**当前这条视频**（别的视频与面板设置不动）；`[全部清空]` 会清所有视频，
> 所以要**连点两次**：第一次只是上膛确认（数据一条不动），5 秒内再点一次才真清。

点开后顶部先显示当前生效值，下面 5 项，填完按「保存」：

```
设置                                    [×]
当前：并发 4 路 · 目标 不限
目标条数 max                    0
并发路数                        4
回复并发                        4
回复间隔 ms                     600
限流等待 s                      10
保存后立即生效（下一次「开始采集」用新值）。面板里设过的项优先于 DSH 插件设置。
[保存]  [恢复默认]  [关闭]
```

| 面板里叫什么 | 存进扩展的字段 | 出厂默认 | 说明 |
| --- | --- | --- | --- |
| 目标条数 max | `maxCount` | 0（不限） | 去重后达到这么多条就自动收工；0 = 一直采到服务端触底（和 DSH 工具参数 `max` 是同一个意思） |
| 并发路数 | `lanes` | 4 | 一轮同时发几路分页请求，1~8 |
| 回复并发 | `replyLanes` | 4 | 二级回复的并发线程数，1~8 |
| 回复间隔 ms | `replyGapMs` | 600 | 同一回复线程两页之间的等待 |
| 限流等待 s | `replyThrottleMaxWaitMs` | 10 | 撞上限流窗口时最多等多久（下限 10 秒，只能放宽） |

- 存在 `chrome.storage.local.dts_user_settings`，**下一次点「开始采集」生效**（面板会提示）。
- 「恢复默认」= 删掉这份设置，回到插件/内置值。
- 这一层**跟 DSH 无关**，用不用 DSH 都有。

### ② DSH 里改（「设置 → 插件 → dsh-douyin-comments」）

在这里改的是**插件每次调用时下发的值**，共 8 项：

| 设置项 | 出厂默认 | 说明 |
| --- | --- | --- |
| 目标条数 `max` | 80000 | 一级评论采到这么多就让扩展「暂停」并落盘；二级回复仍会补完 |
| 并发路数 `lanes` | 4 | 1~8，会覆盖扩展面板那一层 |
| 总超时 `timeoutMs` | 1800000 | 单次采集总超时（30 分钟），到点也会把已采到的落盘 |
| 等扫码秒数 `waitLoginSec` | 180 | 未登录时等你扫码的秒数；0 = 不等，直接返回「需要登录」并把窗口留着 |
| 先清空 `clearBefore` | false | 默认**不清空**扩展里的旧数据（保留断点续采）；true = 开跑前清空该视频旧数据 |
| 回复并发 `replyLanes` | 4 | 二级回复并发线程数 1~8 |
| 回复限流等待 `replyThrottleSec` | 10 | 撞限流窗口最多等几秒（下限 10，上限 600） |
| 回复无进展收工 `replyNoProgressSec` | 900 | 回复阶段连续多久没新数据就收工（下限 60） |

- **改完立即生效**，不用重启 DSH、也不用重装插件：插件每次调用前都现读一遍设置。
- 工具参数（`max`/`lanes`/`timeoutMs`/`waitLoginSec`/`clearBefore`）**只覆盖当次调用**，不会改设置。

### ③ 控制台里写（扩展单独用时）

```js
chrome.storage.local.set({ dts_settings: { lanes: 2, maxCount: 500 } });   // 下一轮采集生效
```

## 三、第一次用要扫码登录（工具会等你，不会硬采）

第一次调用会**弹出一个浏览器窗口**（这是插件自己拉起来的浏览器，不是你日常用的 Chrome/Safari）。
如果抖音没登录，工具**不会开始采集**（未登录采集会被限流、数据残缺），而是：

1. 把登录二维码留在那个窗口里；
2. 默认最多等 **180 秒**，等你用抖音 App 扫码；
3. 扫完它自动继续采集；
4. 如果一直没扫，它会返回 `phase=need-login` 并把**窗口留着**——让 AI 再调用一次即可接着采，
   不用重开窗口、不用重新扫码。

想改等待时长，用上面的设置改 `waitLoginSec`，或者让 AI 带上参数（`waitLoginSec=0` 表示完全不等）：

> 用 douyin_comments 采集 <链接>，waitLoginSec=300

登录态保存在 `~/.dsh/douyin-collector/chrome-profile`（Windows 是 `C:\Users\你\.dsh\...`），扫一次以后都不用再扫。

判定「有没有登录」看的是登录 cookie（`sessionid`/`sid_tt`）：没有就当成未登录，绝不硬采
（实测未登录时抖音页面上常常连登录按钮都探不到，靠界面判断会漏）。真想在未登录下裸采
（数据可能残缺），给 dsh 设环境变量 `DOUYIN_ALLOW_ANONYMOUS=1` 再重启。

## 四、扩展不用你装，它自己装

**不需要**手动「加载已解压的扩展程序」。插件包里自带扩展，每次调用都会校验一遍：

- 没有 → 从插件包里复制到 `~/.dsh/douyin-collector/extension`
- 有但是旧版本（按内容哈希判断）→ 覆盖
- 然后启动浏览器时用 `--load-extension=<那个目录>` 装上

所以「浏览器里没有这个插件」也不影响使用。
（注意：Chrome 不允许任何程序静默往**你自己的** Chrome 里装未打包扩展；插件用的是它自己拉起的浏览器实例，你的 Chrome 不会被改动。）

## 五、结果在哪

- 工具返回值里直接有：`ok`、`count`、`csvPath`、`jsonPath`、`lanes`（实际用了几路）、`title`、前 5 条样本。
- **文件默认落在你自己会话的工作区里** —— `<你的工作区>\douyin-comments\`：
  - `douyin-comments-<videoId>-<时间>.csv`：17 列，带 BOM，Excel 双击直接开，中文不乱码
  - `douyin-comments-<videoId>-<时间>.json`：原始结构（含 `user`、贴纸、二级回复的 `parent_cid` 等）
  - 也就是说：AI 采完，你直接在自己的项目目录里就能看到这两个文件，不用去别处找；
    想换位置就传 `outDir`（或设环境变量 `DOUYIN_OUT_DIR`）。
- **只给本次新采的数据**：结束时按 `cid` 做差集，只交付这一轮新增的评论；
  一条新评论都没采到就返回 `ok=false` 并说明原因（不会把上次的旧数据当成本次结果）。
  想从头采（丢掉断点续采进度）就传 `clearBefore=true`。
- **AI 这条路一次只导当前这一个视频**；想一次导出**本地所有视频**的评论（含以前采过的那些），
  在浏览器面板上把「导出范围」切成 **「全部视频」** 再点导出 —— CSV 会多一列 `video_id`，
  文件名 `douyin-comments-all-<时间戳>.csv`。这个导出是只读的，不会动本地数据。

## 六、参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `url` | — | **必填**。视频链接，或 15~25 位 aweme id |
| `max` | 设置里的值（出厂 80000） | 目标条数（一级评论），到量即暂停并落盘（按页落库，实际通常略多于 max） |
| `lanes` | 设置里的值（出厂 4） | 本次并发路数 1~8；只影响这一次调用，不改设置 |
| `replies` | true | 是否补采二级回复；`false` 更快 |
| `timeoutMs` | 设置里的值（出厂 1800000） | 总超时，到点也会把已采到的落盘 |
| `waitLoginSec` | 设置里的值（出厂 180） | 检测到未登录时，等你在窗口里扫码的秒数；`0` = 不等（直接告诉你需要登录，窗口留着） |
| `clearBefore` | false | 是否先清空扩展里该视频的旧数据（默认 false = 保留断点续采，只交付新采的） |
| `outDir` | `<你的工作区>\douyin-comments` | 输出目录（默认就在你自己会话的工作区里；取不到工作区时才退回 `~/.dsh/douyin-collector/out`） |
| `keepOpen` | false | 调试：采完不关窗口 |

## 七、常见问题

- **换到下一个视频后，上一个视频的数据去哪了？** —— **还在本地，一条都没丢**。评论一直按视频分池
  存在浏览器本地（`chrome.storage.local` 里的 `dts_c_<videoId>`，一个视频一个桶），除了面板那两个
  清空按钮，代码里没有任何删除路径；只是旧面板的「已采（去重）」和导出都只认**当前这条视频**，
  滑到下一条再点「开始采集」时计数从 0 开始，看起来才像被清空了。两个办法立刻看到旧数据：
  ① 看面板上的「**本地已存**」那一行 —— 它显示的就是跨视频总数（`N 个视频 / M 条（本条 X 条）`）；
  ② 把「**导出范围**」切成「**全部视频**」再点导出 —— 所有视频的评论会合成一份 CSV/JSON
  （CSV 末尾多一列 `video_id`，每条都标了它属于哪个视频）。想单独看某一个视频，把链接打开、
  切成「本条视频」再导出即可。
- **点一次「全部清空」没反应？** —— 这是**故意的两步确认**，不是按钮坏了：第一次点只是「上膛」，
  按钮会变成 `确认全部清空？` 并变红，**数据一条都不会动**；要在 **5 秒内再点一次**才真的清空。
  超过 5 秒按钮会自动变回「全部清空」，重新来过即可。只想清当前这条视频的话，点左边的「清空」就够了。
- **「清空」和「全部清空」有什么区别？** —— 「清空」只清**你当前打开的这条视频链接**的评论与去重表，
  别的视频的数据、面板里的设置（齿轮里存的那些）都不动；「全部清空」清掉**所有视频**的评论与去重表
  （面板设置仍然保留），所以需要连点两次。两者都不需要重装扩展，清完下次「开始采集」会自动从头重扫。
- **导出的 CSV 怎么多了一列 / 列数不是 17？** —— 你用的是「全部视频」范围：18 列，末尾一列是
  `video_id`（用来标明每条评论属于哪个视频），**前 17 列的列序和含义一点没变**。
  把「导出范围」切回「本条视频」就是原来的 17 列、文件名也回到 `douyin-comments-<videoId>-…`。
- **面板标题栏上没有设置齿轮 `⚙`**：说明浏览器里装的还是旧扩展（0.2.4 及以前是第三行的「设置」文字按钮，
  0.2.5 起才是齿轮）。插件下次调用会自动把当前版本（0.2.9）复制过去；
  如果这个浏览器窗口是你自己开的，去 `chrome://extensions` 点一下该扩展的「重新加载」，或关掉窗口重开。
- **面板说「已清空」，但评论一条都没落库 / 工具报「落库失败（扩展后台不可达）」**：浏览器里的扩展后台（Service Worker）没起来——常见于手工清缓存时只删了 `Default/Service Worker/ScriptCache`，把指向已删脚本的 `Default/Service Worker/Database` 留了下来。插件 0.5.5 起会自动做「后台可达性」预检（不通就刷新页面重试，最多 2 次），仍不通时会明确报错而不是交付 0 条；手工处理就是关掉浏览器，删掉 profile 里的 `Default/Code Cache` 与**整个** `Default/Service Worker` 目录再开。
- **设置里没有 dsh-douyin-comments 这一项 / 看不到插件**：插件是按 profile 装的，先确认你打开的就是装了它的那个 profile（`dsh plugin --profile web list`）；另外**同一台机器装多个 profile（desktop + web）没问题**，浏览器、登录态、输出目录是共享的，但同一时刻只允许一个采集在跑（第二个会直接报「已经有一个采集在跑」，不会去抢窗口）。
- **重启了 dsh，`douyin_comments` 工具还是不出现**：先看插件的 `peerDependencies`。DSH 启动组装 profile 时会对每个插件做兼容性检查，**只要带 `@deepseek-ai/dsh-` 前缀的 peer 不满足当前 dsh 版本，整个插件会被静默跳过**（只在 stderr 留一行 `skipping profile bundle ...`），所以重启多少次都没用。处理办法二选一：① 用修好 peer 范围的插件版本重新装（`dsh plugin --profile web add file:<新的 tgz>`）；② 临时放行这个版本再重启：`dsh plugin --profile web allow-version dsh-douyin-comments@<插件版本> --dsh-version <你的 dsh 版本> --accept-risk`。
- **报「找不到 Chromium 可执行文件」**：装个 Chrome / Edge / Chromium 即可；插件按
  `PLAYWRIGHT_BROWSERS_PATH` → `%LOCALAPPDATA%\ms-playwright`（Win）/ `~/Library/Caches/ms-playwright`（mac）/
  `~/.cache/ms-playwright`（Linux）→ 系统浏览器的顺序找；最省事是 `npx playwright install chromium`。
  也可以用环境变量 `DOUYIN_CHROME` 直接指定可执行文件绝对路径。
- **macOS 上装了 Chrome 却报面板没出现**：Chrome 137+ 会忽略命令行的 `--load-extension`（品牌版限制），
  插件会打警告。换 `npx playwright install chromium` 装的 Chromium，或 `brew install --cask chromium`，
  再用 `DOUYIN_CHROME=/Applications/Chromium.app/Contents/MacOS/Chromium` 指过去。
- **报「找不到 playwright-core」**：`npm i -g playwright-core`，或在你的 profile 目录里 `pnpm add playwright-core`，或用 `DOUYIN_PLAYWRIGHT` 指定模块目录。
- **二级回复采不到（一级有、二级 0 条）**：把 `replyThrottleSec` 放宽到 60~300、`replyNoProgressSec` 加大，
  或把 `replyLanes` 降到 1~2、`replyGapMs` 加大（刚轰完列表接口时回复接口容易被整段拒）。
- **报「本轮从头到尾没拿到页面签名」**：扩展没真正发出评论请求（视频没有评论区、页面没加载好、或账号受限），把面板提示原文发出来即可定位。
- **一次只能跑一个**：工具声明了不可并发，别同时让两个会话采。
- **觉得太慢或太激进**：改 `lanes`（4 = 实测甜点；1 最温柔，8 最快也最容易被限流）。

## 八、只用扩展（不用 DSH）

1. 解压 `douyin-collector-extension-v0.2.9.zip`，得到 `douyin-collector/` 文件夹；
2. Chrome / Edge 地址栏进 `chrome://extensions`，打开右上角「开发者模式」；
3. 「加载已解压的扩展程序」→ 选中 `douyin-collector` 文件夹；
4. 打开任意抖音视频页，页面右侧会出现采集面板（开始采集 / 暂停 / 导出 CSV / 导出 JSON /
   导出范围（本条视频 / 全部视频）/ 清空 / 全部清空）；
5. 想改目标条数（`max`）、并发路数等，点面板标题栏右上角的**设置齿轮 `⚙`**（0.2.5 起）；
6. 清数据用最后一行两个按钮：「清空」只清当前这条视频链接的评论（别的视频与面板设置不动），
   「全部清空」清所有视频、**需要连点两次**（第一次只是上膛确认，5 秒内再点一次才真清）。
7. 想一次导出**本地所有视频**的评论：把「导出范围」切成 **「全部视频」** 再点「导出 CSV / 导出 JSON」——
   CSV 末尾多一列 `video_id`（共 18 列，前 17 列不变），文件名 `douyin-comments-all-<时间戳>.csv`。
   「本地已存」那一行（`N 个视频 / M 条`）就是跨视频总数，换视频/清空某条视频都不会影响其它视频。

不用 DSH 时并发路数默认 4、目标条数默认不限，也可以在页面控制台里改：

```js
chrome.storage.local.set({ dts_settings: { lanes: 2, maxCount: 500 } });   // 1~8；下一轮采集生效
```
