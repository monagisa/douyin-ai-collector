# 评论分析台 · comment-viewer

一个**纯静态**的抖音评论分析网页：把采集插件导出的评论载进来，自动生成**可交互词云** + **可搜索评论表**，
鼠标悬停词语会放大并弹出悬浮框（能看到说了这个词的评论），点评论即可跳到该用户的抖音主页。

- 无后端、无构建、无依赖：三个文件（`index.html` / `styles.css` / `app.js`），双击 `index.html` 就能用。
- 数据只在**本机浏览器**里处理，不发任何网络请求、不上传服务器。
- 目录结构仿 `dsh-douyin-comments/`，独立可移植：整个文件夹拷给别人即可。

![词云与悬浮框](screenshots/cloud-tooltip.png)

## 关键词过滤（v2.6）

词云的关键词来自 `Intl.Segmenter` 分词，再用三道过滤：

1. 停用词表（约 280 个：单字虚词 + 组合虚词/口头词，如 这种 / 都是 / 才是 / 出来 / 我的）；
2. **字符级启发式** `isFunctionOnly()`：一个词的所有字都属于虚词/代词字符集（`FUNCTION_CHARS`）就整词丢掉；
3. 页面上「过滤虚词」复选框（默认勾上），取消勾选可看原始分词结果。

实词（帐篷 / 露营 / 星空）不受影响；纯表情评论不产生关键词。

## 视觉规范（v2）

界面按 [taste-skill](https://github.com/Leonxlnx/taste-skill) 的 **app screens** 规则重做过一版，要点：

- **中性暗色**：页面 `#0b0b0c`、面板 `#131315`，只用 1px 线分界，不用阴影/渐变/发光/玻璃拟态。
- **色彩只放在数据上**：全站唯一强调色是琥珀 `#e0a94a`，只给词云高频词、选中态和主按钮；其余是中性灰阶。
- **KPI 是一格不是一排卡片**：6 项数据放在同一个容器里，用 1px 竖线切分，数字 24px、标签 13px。
- **字号档位** 12/13/16/20，正文不小于 13px；数字统一等宽对齐。
- **无 hero 标题**：产品名 20px + 一行 scope（`1 个视频 · 398 条评论 · 2 个文件`）。
- **空状态**只留一个气泡 mark、一句话和一个主按钮，不再用整屏遮罩。

## 快速开始

### 方式一（最省事）：双击插件导出的词云 HTML

采集插件面板 v0.5.30 起有 **「导出词云」** 按钮：点一下会把「导出范围 ▾」选中的视频评论打包成
**一个自包含 HTML**（`douyin-wordcloud-<videoId|selectedN>-<时间戳>.html`，词云页 + 数据全内联）。
双击这个文件就能看到完整的词云页（不需要本 README 的源码，也不需要起服务，直接微信/邮件发给别人也行）。

### 方式二：用自己的导出文件

1. 用采集插件/扩展导出评论（`导出 CSV` 或 `导出 JSON`，会得到 `douyin-comments-*.csv/json`）。
2. 打开 `index.html`（推荐起个本地静态服务，见下），点 **打开导出文件…** 选一个或多个导出文件；
   或点 **打开导出目录…** 直接选导出目录（会批量载入目录下所有 JSON/CSV）。
   也支持把文件**拖进页面**。

> 快照模式：如果页面里存在 `window.__CW_BOOT__ = { exportedAt, title, docs: [...] }`（插件导出词云时就靠它），
> `bootFromSnapshot()` 会在启动时直接渲染，不需要再选文件；手动选文件与 `?data=` 两种用法不受影响。

本地静态服务（任选其一，二选一即可）：

```powershell
# 方式 A：Python
python -m http.server 8791 --directory D:\dycopy\comment-viewer

# 方式 B：Node
npx --yes serve -l 8791 D:\dycopy\comment-viewer
```

然后浏览器打开 <http://127.0.0.1:8791/>。

> 直接双击 `index.html`（`file://` 协议）也能用「打开导出文件…」和「打开导出目录…」；
> 只有用 `?data=` 自动载入时才需要 http 服务（浏览器不允许 file:// 下 fetch 本地文件）。

词云布局：阿基米德螺旋 + 矩形碰撞检测（中文不旋转，字号按词频平方根缩放），窗口大小变化或切换「词数」会自动重排。

悬停细节（v2.1 修）：悬浮框是可点的，所以它会挡住下面的词。为了不同时丢掉「能点样例评论」和「悬停一定弹、
弹出的必须是我指的这个词」，做了两件事：

1. 悬浮框只贴在**词云面板内部**、上/下/左/右四个位置里挑「压住词面积最小」的那个，优先不盖住任何词；
2. 鼠标移动时按坐标做**几何命中**（不依赖 `mouseover`），所以即使指针落在悬浮框上、下面还压着某个词，
   也会立刻切到那个词；同时进入新词时会清掉上一个词留下的隐藏定时器（原来快速扫词时新框会被旧定时器关掉）。

回归测试见 `_test_comment_viewer.mjs` 的「快速从一个词扫到另一个词，悬浮框仍显示最后那个词」与
「悬浮框没有盖住正在悬停的词」两条。

高亮规则（v2.2）：亮着的词**永远跟着指针**。指针一离开所有词（含从悬浮框移出、移到词间空白、移出窗口、
移进右侧抽屉），当前词的 `.hot`（放大）和其余词的 `.dim`（变淡）会立即清掉——之前只靠 `mouseout` 清除，
指针经悬浮框离开时那个词收不到事件，就会出现「没悬停也亮着、别的词还变淡」。回归见同一套件的
「鼠标在空白处时没有任何词高亮/变淡」。

## 数据来源与字段

- **JSON（推荐）**：插件/扩展导出的 `douyin-comments-*.json`，`comments[]` 里带完整 `user.sec_uid` → 能跳主页。
  也兼容裸数组 `[...]` 或 `{data:{comments:[...]}}`。
- **CSV**：插件/扩展导出的 `douyin-comments-*.csv`（19 列 / 多视频 20 列，第 2 行是 `# ` 开头的中文说明行，会自动跳过）。
  单视频 CSV 文件名里带 videoId，会自动识别；多视频 CSV 用 `video_id` 列区分。
  需要的列：`cid, text, create_time, digg_count, reply_comment_total, ip_label, level, is_reply,
  user_nickname, user_sec_uid, user_unique_id`。

跳主页需要 `user.sec_uid`（或 CSV 的 `user_sec_uid`）。旧版本导出的 CSV 若没有 `sec_uid` 列，
评论表仍可看，但昵称不可点、悬浮框会提示「该用户无主页信息」。

## 分词

用浏览器内置 `Intl.Segmenter('zh-Hans', {granularity:'word'})` 分词（Chrome/Edge 88+、Safari 16+ 均支持），
不需要 jieba、不加载任何词典文件；老浏览器自动降级为中文 2-gram。

内置一份中文停用词表（的/了/是/就是/什么…、以及「抖音/视频/评论」这类平台词），并过滤纯数字、单字、叠字。

**表情标签先剥离（v2.3）**：抖音表情在文本里是 `[憨笑]` `[流泪]` `[悲伤]` 这种方括号标签，
分词前先用 `/\[[^\[\]]{1,12}\]/g` 去掉，纯表情评论不产生关键词——否则词云里会出现「悲伤/憨笑」这类词，
点进去只有一条 `[悲伤]`。

## 关键词算法（v2.7）

对标 jieba 系中文词云项目的做法（分词 → 词性/停用词过滤 → IDF 权重），但全部在浏览器本地、零依赖：

1. **分词**：`Intl.Segmenter('zh-Hans', { granularity: 'word' })`，分词前先剥掉 `[表情]` 标签；
2. **清洗**：`cleanToken(w, strict)` —— 长度 < 2、纯数字、叠字、停用词（~1100 条，按 jieba 项目常见口径整理）、只由虚词字符组成（`FUNCTION_CHARS` + `isFunctionOnly`）一律丢弃；
3. **权重**：`weight = df × log(1 + N/df)`（`N` = 有文字的评论数，视频内轻量 IDF，不需要外部语料），`df/N > 40%`（样本 ≥ 30 条）判为泛词剔除，字号与排序都按 `weight`；
4. **自定义词表**：侧栏「加词」让长词不被 `Intl.Segmenter` 切碎（如「露营装备」），「屏蔽」从词云里剔除；两组词存在 `localStorage`（`cw.kw.keep` / `cw.kw.block`），只在本机。

实测（8 个导出 / 1541 条）：关键词 986 → **710**，榜首从「评论(161) / 这个 / 才不会」变为「露营 / 帐篷 / 星空」。
